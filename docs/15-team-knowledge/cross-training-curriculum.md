# Team Cross-Training Curriculum & Mastery Framework
## Six-Level System Explanation Guide for All Six Developers

---

## 1. Educational Mandate
The objective of ABHEDYA AI's development model is **not** six isolated specialists who understand only their assigned slice of code. The objective is **six full-system engineers** who can each independently explain, demonstrate, debug, and defend the entire sovereign platform before hackathon judges, plant safety executives, and cybersecurity auditors.

## 3. Level-by-Level Question Rubric

### Level 1: Product & Industrial Context
- *Q1.1:* What physical damage occurs if a refinery pipe suffers unrecognized pitting corrosion?
- *Q1.2:* Why can an industrial operator not upload an ultrasonic thickness log to OpenAI ChatGPT?
- *Q1.3:* What is the core value proposition of ABHEDYA AI in a single sentence?

### Level 2: Architecture & System Boundaries
- *Q2.1:* Draw the canonical data flow from user upload to final `.docx` report.
- *Q2.2:* Where are the four primary trust boundaries located in the system?
- *Q2.3:* What role does the Constitutional Policy Layer play before LangGraph execution?

### Level 3: Implementation & Code Anatomy
- *Q3.1:* How does `WorkbenchState` maintain immutability across LangGraph node transitions?
- *Q3.2:* How does the FastAPI gateway stream real-time node outputs over SSE to Next.js?
- *Q3.3:* How are document chunks indexed in Qdrant, and what metadata is preserved?

### Level 4: Security & Air-Gap Defense
- *Q4.1:* How does the Network Sentinel detect unauthorized outbound socket attempts?
- *Q4.2:* How does the Docker sandbox prevent malicious generated Python code from reaching the host?
- *Q4.3:* What mathematical mechanism makes the PostgreSQL audit ledger tamper-evident?

### Level 5: Operations & Diagnostic Recovery
- *Q5.1:* Demonstrate how to launch the entire stack on a clean machine using Docker Compose.
- *Q5.2:* If the local Ollama daemon crashes mid-task, what error event is emitted and how does the UI handle it?
- *Q5.3:* Run the automated air-gap verification script and explain the terminal output.

### Level 6: Personal Contribution Defense
- *Q6.1:* Exactly what modules and files did you author during this project?
- *Q6.2:* What architectural trade-offs did you make in your workstream?
- *Q6.3:* How does your component gracefully handle a failure in an adjacent subsystem?
